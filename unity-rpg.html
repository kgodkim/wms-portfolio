「일곱 봉인석」

구현한 시스템

게임 기본 시스템을 먼저 끝내고 시나리오로 넘어가는 순서

전투명중 · 회피 · 치명타(레벨별 명중률 표), 방패 막기(정면 ±70°), 전투 자세 전환, 대쉬 · 백스탭, 히트 스톱 · 흔들림 · 밀림, 무기 종류별 공격 속도
성장레벨 99 표. 필요 경험치를 「처치 경험치 × 시간당 처치 수 × 레벨당 목표 시간」 식으로 계산, 스탯 6종 분배와 저장
아이템 · 강화장비 칸 10개, 무기 +15 · 방어구 +10, 안전 +6 이후 확률 표, 3.9초 강화 연출, +7 부터 무기 오라(메시 껍질 3겹 · 흐르는 불꽃 텍스처)
마법 · 변신마법 21개(1~10단계, 버프 · 회복 · 공격 · 약화), 마법서 상점 · 드롭, 직업별 배울 수 있는 목록. 변신 주문서로 1,200초 변신
월드게임 하루 24분 낮밤 · 해 방향, 맑음 · 흐림 · 비 무작위 날씨, 바람에 흔들리는 풀 · 잎 셰이더, 출현 구역 11개 · 동시 54마리, NavMesh 영역 분리(마을 · 몬스터)
UI창 공통 생명주기와 창 스택(Esc 는 맨 위 창만), 원화 상반신을 쓰는 NPC 대화창, 상점 거래 화면, 채팅 창, 회전하는 작은 지도와 클릭 이동
데이터 · 저장수치 표 23개를 JSON 정본으로 두고 MariaDB 로 내보내기 · 가져오기. 실행 시작 때 한 접속으로 읽어 메모리에 올리고, 저장은 백그라운드 UPSERT, 실패하면 파일로 fallback
콘텐츠 묶음1~10장 장면 · 장 전용 몬스터 · 장비 외형을 Addressables 원격 묶음으로, 장에 들어갈 때 미리 읽음(https 만, CRC 검사)
소리배경음악 4곡을 Python 으로 MIDI 작곡 → macOS 내장 GM 음원으로 렌더, 효과음 17종과 빗소리는 코드로 합성
구조상태 있는 관리 클래스는 BasicBiz<T> 싱글턴(Instance 하나만 public), 순수 규칙은 *Rules static, 상속 없는 class 는 sealed (리플렉션 테스트로 검사)

아트 파이프라인

생성 모델 → 감면 · 리깅 → 툰 셰이딩 → 룩북 승인

  1. 설정화인물 · 몬스터 · 소품 2D 그림을 이미지 생성 도구로
  2. 3D 생성면 수 지정 · 자동 리깅 모델(Meshy 7), 인물 3,000 삼각형
  3. Blender 스크립트감면(마을 집 약 200만 → 2만 삼각형), 보스 리깅(뼈 34 · 동작 10)
  4. 툰 셰이딩MToon10 셀 셰이딩 + 법선을 평균한 윤곽선 사본 메시
  5. 룩북 승인정면 · 옆 · 동작 프레임 시트와 GIF 를 사람이 확인한 뒤에만 게임에 반영
  • 캐릭터 2등신 · 원안 얼굴 유지 · 굵은 윤곽선 + 셀 셰이딩을 그림체 기준으로 정하고, 빌드 장면 전부가 툰 재질 · 윤곽선인지 테스트로 검사합니다.
  • 잎 · 풀처럼 잘라 그리는 재질은 윤곽선을 그리지 않고, 그림에 윤곽선이 있는 생성 건물은 윤곽선 사본을 만들지 않는 등 예외를 규칙으로 정리했습니다.
  • 크레딧을 쓰는 생성 호출은 에이전트가 정하지 않습니다. 횟수와 비용을 사람에게 묻고, 도구 설정의 승인 목록(permissions.ask)으로 호출마다 승인 창이 뜨게 고정했습니다.

AI 에이전트 운용

Claude Code · 권한을 나눠 맡김

WMS 프로젝트에서 만든 절차를 게임 개발에 옮겼습니다. 이번에는 기술 결정 권한을 에이전트에 넘기고, 사람은 설계안 결정과 결과 검수에 집중합니다.

사람이 정하는 것

  • 게임 디자인 · 시나리오 · 그림체 · 화면 구성 · 수치 방향
  • 생성 모델 · 동작 · 이펙트의 룩북 승인
  • 크레딧을 쓰는 생성 호출의 대상 · 횟수
  • 에이전트가 올린 결정 요청 이슈(question 34건)

에이전트가 정하고 실행하는 것

  • 구현 방식 · 리팩터링 · 검사와 도구 추가
  • 요청을 이슈로 기록하고 계획 문서에 순서 · 완료 기준을 적은 뒤 개발
  • 개발 중 발견한 기술 문제는 고치고 보고
  • 결정 · 수치가 바뀌면 같은 커밋에서 인수인계 문서 갱신
장치내용
인수인계 문서세션이 바뀌어도 결정을 이어받도록 docs/HANDOFF.md 를 정본으로 두고 세션 시작 때 먼저 읽음. 파일 존재와 규칙 문구를 테스트가 검사
이슈 · 계획모든 요청을 이슈(개선 · 버그 · 결정 요청)로 받고 docs/plan/ 계획 문서 27개에 순서와 완료 기준을 적음. 커밋 메시지 Closes #N 으로 닫음
규칙의 검사화사람이 정한 규칙은 테스트로 고정하고 한 번 깨뜨려 실패를 확인. 예: 주석에 요청 인용 · 날짜 · 과거 경위 금지(CommentRuleTests), 상속 없는 class 는 sealed(ScriptFileTests), Data 계층 public static 금지(BasicBizTests)
장 규칙 · 화면 기준 문서새 장의 상점 · 사냥터 · 경험치 규칙(chapter-rules.md)과 창 · 대화창 · HUD 기준(ui-style.md)을 먼저 읽고 따름
병렬 세션아이템 생성 시험 · 1장 데이터 같은 작업을 별도 세션으로 나눠 진행하고 계획 문서와 이슈로 합침

검증 · 성능

통과하지 않으면 커밋되지 않음

  1. 컴파일 게이트모든 어셈블리 컴파일 오류 · 경고 0 (테스트 · 에디터 포함)
  2. EditMode 테스트593건 전체 통과
  3. 플레이 검사플레이 모드 오류 0, 프레임 진행 확인, 게임 카메라 화면 캡처
  4. 부하 테스트몬스터 60마리 생성 · 처치 5회 + 60초 사냥, 객체 · 재질 · 힙 회귀 확인
  5. 빌드 검사플레이어 빌드 경고 0, 빌드 실행 로그 예외 0, 측정 fps 30 이상
  6. pre-commit 훅마지막 검사가 통과이고 커밋할 파일보다 나중이어야 커밋 허용
  • 부하 테스트로 처치마다 재질이 쌓이던 누수를 찾았고, 빌드 실행 로그 검사로 에디터 검사에 안 나온 예외를 찾았습니다.
  • 전투 이펙트를 종류별 파티클 시스템 8개 재사용 방식으로 바꿔 몰림 구간 플레이어 루프 9~13ms → 6.8ms, 파티클 시스템 92 → 18 로 줄였습니다.
  • 프레임 상한 40(발열 감소), 평균 30 아래로 2초 떨어지면 MSAA → 그림자 → 렌더 배율 순으로 화질 단계를 낮추는 조절기를 두었습니다.
  • MToon 셰이더에 DOTS 인스턴싱 변형이 없어 GPU Resident Drawer 를 켜면 플레이 중에만 물체가 분홍색이 되는 문제는, 에디터 렌더가 아니라 플레이 화면 캡처를 확인해야 보인다는 규칙으로 정리했습니다.
